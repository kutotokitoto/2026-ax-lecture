# app-c "인터랙티브 아트" — 데모 5종 + 허브 종합 플랜

> 상태: **승인됨** (2026-08-10). 앱별 상세 사양이 도착하면 해당 섹션을 보강한 뒤 구현합니다.

## 1. 컨텍스트

사내 바이브 코딩 강의에서 "브라우저 파일 하나로 이런 것까지 된다"를 보여줄 쇼케이스입니다.
청중은 코딩 경험이 없는 엔지니어이고, 목표는 시각적 임팩트 하나입니다.
발표 환경: 내장 GPU 가능성이 있는 노트북 + 프로젝터, 네트워크 없음(또는 불안정).
저장소의 `apps/app-c`(현재 자리표시자)를 이 쇼케이스로 채웁니다. 이름은 **"인터랙티브 아트"**.

## 2. 구조 (사용자 확정)

임무 문서의 project-root를 `apps/app-c/`에 매핑, **허브 + 평면 파일** 방식:

```
apps/app-c/
├── index.html                      ← 허브(전시실). 마지막에 제작
├── PLAN.md                         ← 이 문서
└── apps/
    ├── 01-life-calendar.html       ← 인생 달력
    ├── 02-falling-sand.html        ← 모래 물리 샌드박스
    ├── 03-particle-typography.html ← 파티클 모프 타이포그래피
    ├── 04-fluid-simulation.html    ← 유체 시뮬레이션
    └── 05-solar-system.html        ← 3D 태양계
```

- 각 데모는 단일 HTML 완결(CSS·JS·셰이더 인라인, 외부 요청 0). 파일 하나만 복사해 더블클릭해도 동작.
- 링크 경로: 데모 → 허브 `../index.html`, 허브 → 상위 랜딩 `../../index.html`, 허브 → 데모 `apps/01-….html`.
- 저장소 규칙 6에 따라 마지막 단계에서 최상위 `index.html` 카드(예제 C → "인터랙티브 아트")와
  `README.md` 구조 트리를 함께 갱신.

## 3. 공통 설계

### 3.1 공통 비주얼 가이드

- **배경**: 거의 검정(`--bg0:#05060d`, `--bg1:#0c0f1a`). 프로젝터에서 확실히 어둡게 떨어지는 단색 + 미세 비네트.
- **공통 토큰 + 데모별 시그니처 색** (허브·데모 6개 파일에 각자 소량 복제):

  ```css
  --bg0:#05060d; --bg1:#0c0f1a; --line:rgba(255,255,255,.10);
  --text:#edf1ff; --text-soft:#9aa4c2;
  --c1:#ffc94d; /* 01 인생달력 — 골드(시간) */
  --c2:#ff8a3d; /* 02 모래 — 앰버 오렌지 */
  --c3:#3fd3ff; /* 03 타이포 — 시안 */
  --c4:#ff4fa0; /* 04 유체 — 마젠타 */
  --c5:#b48cff; /* 05 태양계 — 라이트 바이올렛 */
  ```

  시그니처 색은 각 데모의 타이틀·UI 강조와 허브 액자 테두리에서 일치시킵니다.
  데모 내부 콘텐츠 팔레트(타이포 5색 그라데이션, 유체 HSV 순환, 모래 원소색)는 별도입니다.

- **금지**: 저대비 그라데이션, 1px 헤어라인, 회색 위 회색 텍스트. UI 텍스트는 `#e8ecf4` 이상 밝기.
- **타이포**: 시스템 스택 고정 — `Pretendard, -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans KR", "Malgun Gothic", system-ui, sans-serif`. 숫자·수치는 `font-variant-numeric: tabular-nums`.
- **테마 규칙(저장소 규칙 4)과의 관계**: 프로젝터 요구로 **다크 단일 룩으로 고정**합니다.
  색은 CSS 변수로 정의하되 `prefers-color-scheme` 분기는 두지 않습니다.
  (lecture-01, app-b 게임 화면과 같은 기존 예외 선례를 따름 — 확정 사항)

### 3.2 공통 UI 패턴 (전 데모 동일, 코드는 파일별 소량 복제)

- 레이아웃 규약: 좌상단 `NN · 제목`(시그니처 색) · 좌하단 `← 허브`(`../index.html`) · 우하단 FPS/품질 배지(기본 숨김). UI는 마우스 유휴 시 페이드아웃.
- 단축키 (전 데모 공통, 도움말 오버레이에 표기):
  - `R` 리셋 · `F` 전체화면 · `H` 도움말 · `P` FPS/품질 표시 토글 · `Space` 일시정지(해당 시)
  - 데모별 고유 키는 각 앱 섹션에 명시
- 첫 진입 시 힌트 토스트("드래그해 보세요" 등 데모별 1문장), 첫 입력 후 페이드아웃.
- **품질 자동 하향(공통 패턴, 각 파일에 ~40줄 복제)**: 워밍업 1.2초 버림 → 60~90프레임
  frameMs **중앙값 > 26ms**면 한 단계 하향(app-b `AX.Quality` 검증 기준). 하향 시 재측정해
  LOW까지 내려갈 수 있고, 자동 상향은 없음(발표 중 출렁임 방지) — 상향은 수동 키만.
  하향 시 "품질 자동 조정됨" 토스트 2초. 앱별 세부 임계·티어 구성은 각 앱 섹션 참조.
- `prefers-reduced-motion` 대응: 자동 연출(어트랙트 모드 등)만 정지, 직접 조작은 유지.
- `localStorage`(티어 기억 등)는 try/catch — `file://`에서 실패해도 무해하게.

### 3.3 허브(랜딩) 설계 (`index.html`, 자리표시자 전면 교체 — 마지막 단계)

**컨셉 확정: "심야 전시실(네온 갤러리)"** (사용자 선택. 8비트 월드맵 안은 기각)
- 어두운 미술관 전시실: 짙은 배경 위 스포트라이트 원뿔광(CSS 라디얼 그라디언트) 아래 **액자 5개**,
  액자 속 = 각 데모의 **살아 있는 절차 미리보기 캔버스**(180×120 내외, 각 40~80줄, 30fps 스로틀):
  01 격자 도트 차오름 · 02 미니 낙하 모래 · 03 점 200개가 "가"로 모임/흩어짐 ·
  04 잉크 소용돌이 · 05 미니 궤도+태양 글로우.
- 액자 아래 놋쇠 명판: 번호·제목·한 줄 설명 + "재료: HTML Canvas, 절차 노이즈 / 2026" 풍 표기.
  호버·포커스 시 스포트라이트가 밝아지고 액자가 살짝 전진. 액자 테두리는 데모별 시그니처 색.
- "인터랙티브 아트" 정체성에 부합하고, app-a(레트로 하드웨어)·app-b(밝은 쇼룸)와 완전히 구분됨.
- 키보드: `←→` 관람 동선 이동, `Enter` 감상(진입), `1~5` 직접 진입, `ESC` 상위 랜딩.
  20초 무입력 시 스포트라이트가 액자를 자동 순회하는 어트랙트(아무 키로 해제).
  상단 `← 목록으로`(`../../index.html`) 상시 노출.
- 성능: 부하원은 미리보기 5개뿐. `document.hidden` 시 전체 정지, 첫 2초 평균 >25ms면 미리보기를
  정지 프레임으로 전환하는 안전판 1단.
- 리스크: ① 미리보기 상시 구동 부하 → 호버/포커스 액자만 애니메이션으로 축소(plan B)
  ② "전시실" 톤이 강의 맥락에서 과할 수 있음 → 명판 문구를 유머 섞인 한국어로 눌러줌.
- 규모 ~900~1,100줄, 난이도 중(미리보기 5개의 "분위기 압축"이 최대 공수).

**허브 완료 체크리스트**: file:// 단독 동작·외부 요청 0 / 액자 5개 살아 있는 미리보기 + 클릭·Enter
진입 / 키보드만으로 전 데모 진입 / `../../index.html` 복귀 / 시그니처 5색이 액자·데모 타이틀에서
일치 / 프로젝터에서 명판 판독 가능 / 탭 비활성 시 CPU 급감.

## 4. 앱별 플랜

### 4.1 앱 01 — 인생 달력 (`apps/01-life-calendar.html`)

**알고리즘·렌더링**
- **캔버스 단일 드로우** (DOM 4,680개 기각 — 순차 채움 애니메이션에서 스타일 재계산 폭풍, 캔버스는 프레임당 fillRect 수십 회로 1ms 미만).
- 격자는 **가로형 90열(나이)×52행(주)** — 16:9 프로젝터에 맞고 "왼쪽→오른쪽=시간"으로 직관적. 인생 구간 오버레이가 세로 밴드가 되어 라벨이 쉬움.
- 셀 크기 `unit = floor(min(availW/90, availH/52))`, 1920×1080 기준 셀 11px+gap 3px. **디바이스 픽셀 정수 정렬**(dpr 상한 2)로 소형 셀 번짐 차단.
- 셀 객체를 만들지 않음: `filledCount` 정수 + 최근 채움 링버퍼(64)만. 색인→좌표는 `col=floor(i/52), row=i%52`.
- 날짜 계산은 로컬 자정 기준 일수 차 → `floor(/7)` 단일 경로 (UTC 파싱 금지 — 타임존 오차).
- 레이어 3장: L0 빈 격자(1회 베이크) + L1 채움 누적(프레임당 신규 셀만 추가) + 글로우 스프라이트 1장 프리렌더 → 메인에 합성.
- 채움 연출: 총 `T = clamp(pastWeeks/300, 4, 8)`초, easeInOutCubic — 초반 가속, 마지막 2초 감속 후 현재 주 착지(파문 1회 + 1.6초 주기 펄스). 통계 숫자는 채움과 동기 카운트업.
- 인생 구간 밴드(유년기~노년, 알파 0.08) + "지금" 세로 가이드.
- 감정 문구 3종 로테이션: "여름이 앞으로 약 54번 남았습니다" 류.
- 입력: date input + **프리셋 3개(1975/1990/2005년생)** + 재생·리셋. 로드 시 기본 프리셋 자동 재생. 호버 시 "만 n세 · yyyy년 m월경" 툴팁(DOM div 1개). 키: `Space` 재생/정지, `1~3` 프리셋.

**성능**: 프레임 사용 ≈3ms로 여유 큼. 하향 1단계 dpr 2→1·글로우 30→10개, 2단계 글로우·팝·파문 오프(본질 연출은 유지).

**리스크 top 2**
1. 1280×720 프로젝터에서 셀 과소 → plan B: 셀 최소 6px 보장, 통계 패널 하단 접기, gap 1px 축소.
2. 날짜·주 계산 오차(타임존·브라우저 편차) → plan B: 단일 계산 경로 + 시연은 프리셋 위주, 90세 초과 입력 방어.

**30초 시나리오**: 열기(자동 재생, 3–9s 차오름·카운트업) → 착지·펄스·감정 문구(9–13s) → [1975년생] 클릭으로 세대 대비(13–18s) → 호버 툴팁 멘트 → 청중 생일 즉석 입력 예고로 마무리.

**완료 체크리스트**

- [ ] 로드 직후 자동 채움 시작, 6초 내외 완료, 현재 주 펄스가 3m 뒤에서도 식별

### 4.2 앱 02 — 모래 물리 샌드박스 (`apps/02-falling-sand.html`)

**알고리즘·렌더링**
- 원소 11종 + 스트레치 1종: 벽·모래·물·기름·불·연기·증기·식물·용암·돌·산(酸), 여유 시 화약(폭발). 팔레트 UI 노출은 9~10종, 연기·증기·돌은 파생 전용.
- 반응표 핵심: 불+기름=폭주 확산(p0.8) · 불+물=증기(p0.9) · **용암+물=돌 생성**(p1.0) · 산은 고체 용해 · 물+식물=성장(과밀 방지) · 증기 수명 만료 시 p0.35로 **비가 되어 내림** · 밀도 침강(모래는 물에 가라앉고 기름은 뜸, p0.7 swap).
- 그리드 가로 320 고정(세로는 종횡비 따라 ~180-200, LOW는 240). **단일 버퍼 in-place + `stamp` 프레임 스탬프**(이중 이동 방지) — 장르 표준이고 이중 버퍼보다 충돌 해소가 단순.
- `Uint8Array` 4장(cells/life/rnd/stamp, ~256KB). 스캔: bottom-up(가루·액체) + top-down(기체), 행별 좌우 방향을 `(행+프레임) 홀짝`으로 교대해 편향 제거. 액체는 확산 계수(물4·기름2·산3·용암1)만큼 수평 탐색해 수면 평탄화.
- 렌더: `ImageData`를 `Uint32Array` 뷰로 직접 기록(팔레트 룩업, 셀별 고정 난수 `rnd`로 모래알 질감, 불·용암은 프레임 섞어 일렁임) → `image-rendering: pixelated` 확대. HIGH 티어만 가짜 블룸(`ctx.filter='blur(6px)'`+`lighter` 1회 겹침).
- 브러시: 원형, 휠 1~24, 드래그 선형 보간 도장, 우클릭 지우개, 숫자키 원소 전환.
- **초기 씬 절차 생성**: 모래 언덕 + 물 분지 + 식물 + 돌 선반 위 기름 웅덩이 + 벽으로 밀봉한 용암 챔버(발표 때 뚫는 용) + 3초 모래 낙하 연출.

**성능**: 64,000셀×2패스 ≈ 3~5ms, 총 ~8ms로 여유 50%. 티어: HIGH(320·블룸·dpr2) → MED(블룸 off·dpr1.5) → LOW(240·dpr1). 하향 시 기존 씬을 최근접 리샘플로 유지.

**리스크 top 2**
1. 저사양 CPU+4K에서 CPU 바운드 → plan B: 기체 패스 격프레임 + 시뮬 30Hz/렌더 60Hz 분리(처음부터 구조 분리).
2. 액체 진동·체커보드 → plan B: 수평 이동을 p0.5 랜덤 워크로 완화 + 확산 계수 보상, 파라미터 상수 블록 집약.

**30초 시나리오**: 초기 씬 소개(0–5s) → 물에 모래(가라앉음)·기름(뜸)(5–10s) → 기름막 점화 폭주(10–15s) → 물 투하→증기→비(15–20s) → 용암 챔버 벽을 지우개로 개방→물과 만나 돌 다리 생성(20–28s) → 산으로 돌 용해 마무리.

**완료 체크리스트**
- [ ] `file://` 동작, 콘솔 에러 0, 로드 직후 절차 씬+모래 낙하 연출

### 4.3 앱 03 — 파티클 모프 타이포그래피 (`apps/03-particle-typography.html`)

**알고리즘·렌더링**

### 4.4 앱 04 — 유체 시뮬레이션 (`apps/04-fluid-simulation.html`)

Stable Fluids(Stam) 계열, Pavel Dobryakov WebGL-Fluid-Simulation(MIT) 구조 참조 재작성.

**컨텍스트·확장 검사 사다리**
1. WebGL2 + `EXT_color_buffer_float`(RGBA16F 렌더 타깃) →
2. WebGL1 + `OES_texture_half_float`(±`_linear`; 선형 미지원이면 이류 셰이더 수동 4탭 바이리니어) →
3. 각 포맷은 1×1 테스트 FBO의 `checkFramebufferStatus`로 실검증(확장만 광고하는 드라이버 방어) →
4. 전부 실패 시 **Canvas2D 간이 모드**(가산 트레일 파티클 ~300개, ~80줄)로 자동 전환 + "간이 모드" 배지. 데모가 빈 화면으로 죽지 않는 것이 목적.

**텍스처·패스**: 속도 128(RG16F 더블) · 염료 512(RGBA16F 더블) · 압력/발산/컬 128 · 블룸 체인 7단. 공용 풀스크린 삼각형 + 프래그먼트 셰이더 ~13개 전부 JS 문자열 인라인. 루프: splat → curl → vorticity(CURL 30 — 소용돌이 유지가 "우와" 담당) → divergence → 압력 clear(×0.8) → Jacobi 20회(LOW 12/HIGH 28) → gradient subtract → 속도 이류(반라그랑주, 소산 0.2/s) → 염료 이류(소산 1.0/s, 잔상 길이 튜닝 지점) → 표시(의사 노멀 셰이딩 + 블룸). dt는 1/60 클램프(불안정 방지). **블룸 채택, sunrays 제외**(+150줄 대비 체감 이득 작음).

**색·입력·자동 데모**: HSV 고채도 순환(드래그 중 0.15초마다 hue 전진 → 무지개 리본) × 0.15 주입 후 블룸이 하이라이트. 휠=반경, `C` 다색 버스트, `B` 블룸, `Q` 품질 수동 순환, `R` 클리어. **유휴 4초 시 리사주 경로 자동 splat(attract 모드)** + 로드 직후 8방 버스트 1회 — 손 안 대도 살아 있는 첫 화면. 리사이즈 시 염료 blit 보존.

**성능**: 병목은 시뮬이 아니라 표시 패스+블룸(화면 픽셀 수) → DPR 상한이 최대 손잡이. 티어: HIGH(속도192/염료1024/Jacobi28/블룸on/dpr2) → MED(128/512/20/on/1.5) → LOW(96/256/12/off/1). 초기 티어는 `창너비×DPR>2600`이면 MED. WebGL1 폴백이면 MED 이하 고정.

**리스크 top 2**
1. half-float 렌더 타깃 미지원 → plan B: 검사 사다리 + Canvas2D 간이 모드(위).
2. iGPU+4K 필레이트 부족 → plan B: 백킹 스토어 절대 상한 1440px 캡 + CSS 확대(유체는 업스케일 열화 거의 안 보임) + 블룸 강제 off — LOW 아래 "최후 단계"로 내장.

**30초 시나리오**: 로드 버스트+attract(0–4s) → 큰 S자 드래그로 무지개 리본(4–12s) → 작고 빠른 원으로 소용돌이 쌍(12–18s) → `C` 연타 발광 절정(18–24s) → 휠 최대로 전체 휩쓸고 손 떼기, attract가 이어받아 여운(24–30s).

**완료 체크리스트**
- [ ] `file://` 동작, 콘솔 에러 0, 로드 버스트 + 4초 방치 시 attract 모드
- [ ] 드래그 리본 무지연 추종, 소용돌이 수 초 유지

규모 약 1,300~1,600줄, 난이도 상(알고리즘보다 폴백 매트릭스 검증이 관건).

## 5. 구현 순서와 검증 절차 (임무 문서 고정 순서)

```
① 01 인생달력 → ② 02 모래 → ③ 03 타이포 → ④ 04 유체 → ⑤ 05 태양계 → ⑥ 허브(마지막)
```

- 한 번에 앱 하나. 앞 앱이 사용자 브라우저 검증을 통과하기 전 다음 앱 착수 금지.
- 각 앱 완성 시: 파일 경로 + 브라우저 확인 체크리스트 보고 후 정지, 사용자 검증 대기.

## 7. 확정된 기술 결정 (기록)

- three.js: **r147 UMD 인라인 + 자작 궤도 카메라** (근거·입수 절차는 4.5). 구현 시점에
  네트워크로 소스 1회 다운로드 필요(발표장이 아니라 작업 환경 기준이라 문제없음).
- 테마: 다크 단일 룩 고정, `prefers-color-scheme` 분기 없음 — 코드 주석으로 저장소 규칙 4의
  의도적 예외임을 명시(app-b "게임 화면은 늘 어둡다" 선례).
- 품질 하향: 전 앱 공통 중앙값 26ms 룰(3.2), 하향 전용, 수동 상향.
- WebGL 계열 앱(04·05)은 실패 시 반드시 한국어 에러 카드/간이 모드 — 빈 화면·무한 스피너 금지.
